# 聊天与消息中心设计

## 目标

为顾客端和商家端提供实时私聊、家庭群聊和统一的持久化消息中心。

## 架构

聊天写操作使用 REST，确保权限、首条消息限制和家庭成员变动在服务端事务中校验。WebSocket 只负责向已登录的顾客和商家推送 `CHAT`、`NOTIFICATION` 事件，前端收到后刷新列表、详情和未读数。

新增后端 `message` 模块及四类数据：会话、会话成员、聊天消息、系统通知。所有聊天主体统一使用 `users.id`；商家会话对象解析为店铺所有者用户，不能使用 `shopId` 代替用户身份。

## 权限与私聊

顾客与商家账户均新增 `allowPrivateChat`，默认 `true`。顾客另有 `autoJoinFamilyChat`，默认 `true`。设置通过账户设置页和账户 API 持久化。

顾客可从店铺详情右上角与该店铺所有者发起私聊；可在聊天页按昵称搜索顾客并发起私聊。服务端仅允许对方已开启私聊权限的会话创建，并在新会话中记录发起人。发起人首条消息发出后，必须等对方至少回复一次才能继续发送。

## 家庭群聊

商家可在本店已审批家庭成员不少于两人时创建一个家庭群；每个店铺最多一个家庭群。群封面默认使用家庭封面。商家和自动加入已开启的成员直接进入群；未开启自动加入的成员处于待确认状态，确认后加入。

已创建家庭群在成员数降至一人或以下时保留，但家庭管理页不再提供新建入口。成员退出家庭时自动退出群；成员可单独退群并在仍属于家庭时后续申请重新加入。商家可将指定家庭成员移出家庭群，但不得借此移出家庭；被移出者保留家庭资格并可后续申请重新加入群。商家解散家庭群后保留历史并禁止发送消息。

家庭群详情展示群名称、封面、成员、公告和群状态。商家可编辑群名称、封面和公告；商家与家庭成员都可为本人开启或关闭该群的消息免打扰。免打扰只抑制该用户的即时提醒，不影响未读数、历史消息或群成员资格。

## 菜品分享

顾客端菜品详情增加“分享”入口，可将菜品卡片分享至已存在的单聊或群聊。公开店铺菜品可分享至任意可发送的会话。家庭店铺菜品只能分享给同一家庭店铺的已审批家庭成员，或分享至该家庭店铺对应的家庭群；服务端拒绝向其他个人或群聊分享，并返回不可分享提示。分享消息保存菜品 ID、店铺 ID、菜品名称、图片和价格快照，接收方可进入对应店铺菜品详情。

## 消息中心

顾客端和商家端均提供聊天/消息中心和未读数。订单处理结果、反馈回复、家庭审核结果写入顾客系统消息；新订单、家庭申请、新顾客反馈写入商家系统消息。系统消息支持列表、已读、全部已读和未读数。

## 前端入口

顾客端在已登录状态下的底部导航中间增加聊天页；店铺详情右上角提供聊天按钮；个人资料页提供聊天权限设置。

商家端增加底部聊天入口和工作台快捷入口；商家资料页提供私聊权限设置；家庭管理页提供家庭群创建/解散和群状态入口。

## API 与事件

新增会话列表、私聊创建、聊天记录、发送文本/菜品消息、家庭群创建/解散/加入/退出/成员移除、家庭群资料编辑、群免打扰和系统消息 API。WebSocket 事件使用 `CHAT/MESSAGE_CREATED`、`CHAT/CONVERSATION_UPDATED`、`CHAT/MEMBER_UPDATED`、`NOTIFICATION/CREATED`、`NOTIFICATION/READ_CHANGED`；事件载荷包含会话或通知 ID 与未读数。

## 验证

后端覆盖权限、首条消息、会话去重、家庭群成员同步、群资料权限、免打扰和家庭菜品分享范围；前端覆盖 API 模型、未读数、WebSocket 刷新、聊天入口和分享入口。最终运行后端 Maven 测试与两个 Flutter 工程的分析、测试。
