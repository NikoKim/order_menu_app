# 顾客端 WebSocket 设计

## 目标

让顾客端的“我的订单”“留言建议/反馈记录”“我的家庭”在后端事件发生后自动更新。

## 方案

顾客端新增一个共享的 WebSocket 服务，使用已存在的 `web_socket_channel` 连接后端 `/ws/customer?token=<JWT>`。登录成功后建立连接，退出登录时关闭连接。

页面仍用现有 HTTP 接口完成首次加载和网络异常时的手动刷新。WebSocket 只接收后端推送；根据 `module` 和 `action` 分发事件，三个相关页面收到各自事件后重新加载数据。

服务发送定期 `PING`，并在意外断开时以有限次数、递增间隔重连。连接错误不会阻塞页面使用。

## 消息约定

复用后端统一消息格式：`module`、`action`、`data`、`timestamp`。订单、反馈和家庭模块各自映射为独立的页面刷新事件；未知消息安全忽略。

## 验证

为消息解析和模块事件分发添加 Flutter 单元测试；运行格式化、静态分析和相关测试。后端不改变既有推送格式，仅在缺失时补充顾客事件推送。
