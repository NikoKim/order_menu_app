# 娱乐模块：猜股票

## 当前交付范围

- 娱乐前端只放在 `moments_web_frontend`，入口位于“动态”旁的“娱乐”。
- 本期完成桌面和手机浏览器响应式 Web；Flutter/原生手机客户端不在本期范围。
- 登录顾客可以创建、编辑、发布和停用股票游戏；游客可以使用浏览器身份游玩。
- 每个已发布股票游戏独立统计版本排行榜，按最终现金相对各自初始资金的收益率排名并立即公开；收益率相同再按最终现金排序。
- 娱乐核心与 `GUESS_STOCK` 玩法分层，后续玩法复用游戏、版本、场次、身份、房间和排行榜能力。

## 版本、密钥与配置界面

- 编辑器按基础、AI、银行、事件、版本与密钥分栏；AI 每页 2 个，事件池分页，银行编辑不分页。游戏介绍页的事件池也使用分页；Web 下拉框统一使用挂载到页面顶层的自定义选择器，避免被父容器裁切。
- `version_no` 是内部不可变修订号，作者填写的 `version_label` 是排行榜逻辑版本。同一标识的多次发布共享排行榜分组，并按玩家身份保留最好成绩；改变标识才开启新分组。
- 游玩密钥支持单人、多人、通用三种范围，以及一次、有限次、不限次数。删除后永久失效；服务端只保存 SHA-256 摘要和脱敏提示。
- 创建者托管 AI 是默认来源，不会锁死玩家选择。玩家仍可使用账号默认 AI 或本局自己的 Key，显式玩家配置优先。

## 贷款期限与延期

- 银行 `maturityRounds` 是玩家可选期限上限，借款时可选 1 到该上限的整数回合。融资页返回并展示全部合同、本息、利率、原/当前到期回合、剩余期限和延期记录。
- 活动合同可在到期前延期，每笔最多 2 次、每次 1 到 2 回合。延期费为剩余本金的 0.5%，立即扣款；每次延期把回合利率提高 0.2 个百分点。禁借、强平、违约状态不能延期。

## 回合状态机

一个股票回合包含两个交易子阶段：

```text
OPENING_EVENT_ACK（仅抽到事件时）
  -> OPENING_TRADING
  -> OPENING_RESULT_ACK
    -> CLOSING_EVENT_ACK（仅开盘未出现事件、收盘新抽到事件时）
  -> CLOSING_TRADING
  -> ROUND_RESULT_ACK
  -> 下一回合或最终结算
```

- 多人事件确认和两个结果弹窗均无倒计时，并等待全部有效真人确认。
- 单人 `AUTO` 支持 x1、x1.5、x2、x3、x5；倍速同时缩放两个交易阶段、AI 任务时间和 3 秒事件/结果停留时间。开启自动进入下一阶段后由服务端权威状态机推进，关闭后仍由玩家点击确认。
- `AUTO` 的两个交易阶段以 `tradingSeconds / 倍速` 计时；`MANUAL` 不提供倍速和自动推进，全部真人确认后结算本阶段。
- 自动交易倒计时归零时，Web 立即锁定股数输入、滑块、比例、“全部”和撤单按钮，不等待下一次轮询才禁用；服务端仍是最终截止时间权威，避免临界时刻继续提交并收到 400。
- AI 每个交易子阶段独立决策；手动模式按钮同时展示真人确认状态和 AI 决策状态。
- 当前回合只有价格实际生成后才加入走势图，不预画未来节点。

## 买卖与价格公式

创建者配置 `marketLiquidityShares`，范围 100～10,000,000，默认 1,000 股/参与者，并配置 `maxBuyQuantity` 单次买入上限。设参与人数为 `N`，订单影响上限为 `C`。

开盘前只允许买入：

```text
买盘影响% = C * tanh(全场买入股数 / (marketLiquidityShares * N))
开盘价 = 上一回合收盘价 * exp((开盘基础变化% + 开盘事件变化% + 买盘影响%) / 100)
```

所有买单按计算后的开盘价成交。普通订单取用户输入、`maxBuyQuantity` 和 `floor((现金 - 冻结现金) / 上一回合收盘价)` 三者最小值；“100%”代表用满该普通订单额度。“全部”订单不受 `maxBuyQuantity` 限制，清算时根据实际开盘价反复求解 `floor(全部可用现金 / 实际开盘价)`，购买尽可能多的整数股。两类订单均不会令现金变成负数。

收盘前只允许卖出且不允许卖空：

```text
卖盘影响% = C * tanh(全场卖出股数 / (marketLiquidityShares * N))
均值回归% = clamp(-18% * ln(开盘价 / 上一收盘价) * 100, ±基础波动率的 50%)
收盘价 = 开盘价 * exp((收盘基础变化% + 收盘事件变化% + 均值回归% - 卖盘影响%) / 100)
```

所有卖单按计算后的收盘价成交。开盘、收盘基础变化使用独立的截断正态分布，降低均匀随机造成的极端值密度；对数收益公式保证同幅上涨与下跌对称且价格始终为正。最后一回合不会自动卖出；结算时剩余持仓按最终收盘价直接折算为现金资产，不生成订单，也不改变最终价格。

新建游戏默认使用 `pricingEngineVersion=V2`；旧配置缺少版本时保持 `V1`，历史和已发布旧版本不会被新公式改写。V2 使用统一 `TrendState + VolatilityState`、带滞后的状态切换、随趋势年龄衰减并受疲劳抑制的动量、EMA20/EMA50 中期回归和具有冲击记忆的动态噪声。每回合保存状态、年龄、动量、事件传导、中枢回归、噪声和总变化，收盘复盘弹窗展示这些分解。

## 事件规则

- 每个新场次以游戏版本种子、场次 ID、安全随机数和高精度时钟生成独立混合种子；同一场次可稳定恢复，新开场次不会复用相同事件、涨跌幅和 AI 时间轨迹。
- 开盘前按混合种子对尚未发生的启用事件做与上传/CSV 行顺序无关的确定性洗牌，再取候选并只按该候选自身发生率掷一次；可能没有事件。
- 若开盘前出现事件，进入收盘前不重复显示事件弹窗；沿用已经公开的事件和方向，但使用独立随机序列重新判断影响概率，并在影响时重新生成幅度。开盘与收盘的生效状态和幅度分别存储，互不复用。
- 若开盘前没有事件，收盘前再独立抽取一次；收盘事件只参与收盘价。
- 事件增加 `eventType`、`relevance`、`credibility`、`surprise`、`strength` 五类公开元数据。旧版本缺少这些字段时分别按行业、中相关、已确认、一般意外和中强度兼容。
- 事件影响不再是“未生效或区间内均匀随机的完整影响”。系统先按影响概率得到无影响、轻微、常规或强烈层级，再从配置区间使用截断正态分布生成原始幅度，中间值更常见、边界值更少见。
- 定价前根据最近最多 6 个已完成回合识别上涨、下跌、震荡、过热、超卖或高波动状态。事件最终幅度由层级、相关度、可信度、意外程度、事件强度、市场状态和本阶段基础走势共同调整，并受事件最大幅度及基础波动率上限约束。
- 随机方向会参考市场状态：过热时更可能形成负向修正，超卖时更可能形成正向修正，趋势状态按 65% 概率顺势；固定方向不被改写。开盘事件进入收盘阶段时仍保持已经公开的方向。
- 每个阶段保存原始影响、最终影响、影响层级、市场状态、适配比例和自然语言原因。价格生成前后端不会返回这些结果字段；生成后 Web 同时展示实际变化和因果说明。
- 已经实际出现的事件本局不会再次出现。事件数量没有业务上限。
- 连续 5 个完整回合没有产生事件时，下一回合跳过候选的发生率掷骰并保证出现一个尚未使用的启用事件；事件池耗尽时无法强制。
- 事件弹窗在价格生成前显示名称、介绍和五类公开元数据并暂停计时；价格生成后才显示影响层级、实际变化和自然语言原因，不使用“生效/失效”术语。
- 开盘与收盘结算弹窗使用更大的独立“事件结果”区域；有事件时说明它造成的实际价格变化，没有事件时明确显示本阶段或本回合未发生随机事件。
- CSV 在浏览器内解析和预览，支持追加或替换；下载模板使用 UTF-8 BOM。模板包含一个可编辑的 `EVENT` 示例，以及逐字段说明、合法枚举和理论建议值的 `GUIDE` 行。导入自动忽略 `GUIDE` 行，旧版没有 `rowType` 的 CSV 保持兼容，服务端仍逐项校验。
- 理论建议以玩法平衡为目的：日常事件通常发生率 5%～25%、影响率 60%～90%、原始幅度 0.5%～4%；罕见重大事件通常发生率 1%～8%、影响率 85%～100%、原始幅度 3%～8%。传闻应降低可信度和影响率，不建议常规事件最大幅度超过 10%。这些区间不是现实证券市场统计结论。
- V2 事件先计算总冲击，再按事件类型拆成可审计的跨阶段切片；突发/情绪前置消化，政策/行业缓慢传导。同类型同方向事件在最近 5 回合按 `1 / (1 + count × 0.35)` 边际递减；高相关、已确认、显著超预期的反趋势事件在成熟趋势中可放大 1.35 倍。普通事件、强事件和同类型事件分别使用不同冷却窗口，暂停恢复不会重复释放切片。

## AI 与多人

- AI 游戏的单人玩家仍可在开局时选择“不使用 AI”；选择加入后，模型通过创建者固定配置、用户默认配置或本局 OpenAI-compatible API Key 参与策略复核，本地策略持续执行两个交易阶段，避免每阶段都请求模型。
- 多人只有房主可以决定是否加入 AI，并配置一次本房间 AI；其他成员不提供 Key。
- 登录顾客可以保存、修改、删除默认 AI 配置，响应永不返回 API Key。房主可直接使用默认配置。
- 游戏创建者还可以为某个已发布游戏提供固定 AI 配置。玩家单人开局和多人房主均可直接使用该配置，无需填写自己的 Key；固定 Key 只在服务端加密保存，接口永不返回明文，调用费用由创建者配置的账号承担。
- API Key 用 AES-GCM 加密，只用于本场，结束或放弃后物理删除；默认配置除外，直到用户修改或删除。
- AI 采用“持续投资观点、目标股票敞口、服务端约束执行”的架构。每个 AI 同时最多维护一个 `ACTIVE` Thesis，记录观点编号/版本、建立回合与价格、方向、市场状态、目标敞口、置信度、复核周期、有效期和结构化失效条件。历史观点保留为 `INVALIDATED` 或 `CLOSED`，不会覆盖后丢失。
- Agent 不再输出 `BUY/SELL/HOLD` 或股数，只输出 `CREATE_THESIS/KEEP/ADJUST/REPLACE_THESIS/CLOSE_THESIS`、目标股票敞口、方向、紧急度和观点内容。服务端用当前敞口与目标敞口差自动推导交易方向；`KEEP` 必须保持目标、方向和失效条件，`ADJUST` 不能改变核心方向，方向反转必须替换观点。
- 每个交易阶段冻结最多 50 回合的共享公开行情。模型包按“固定系统规则 → 共享行情/公开财报/已结算对手行为 → 私有持仓/观点/研究”排序，公开信息与私有数据隔离；数值裁剪冗余精度，最多发送最近 12 个收盘价和多周期统计，不发送未来价格、隐藏冲击切片或其他参与者待成交目标。
- 失效条件限定为后端可执行的 `PRICE_BELOW/ABOVE`、`RETURN_BELOW/ABOVE`、`DRAWDOWN_ABOVE`、`VOLATILITY_ABOVE`、买卖盘失衡、事件方向/类型和观点年龄。后端先产生已触发条件和新证据，再由 AI 决定关闭、调整或替换观点，模型不能推翻自己已经触发的客观条件。
- 五种 Persona 由模型观点与本地战术共同实现。战术状态包括 `OBSERVE/PROBE/ACCUMULATE/RIDE/DISTRIBUTE/EXIT`，持久化于 AI 任务的 `strategy_state_json`，保留模型核心理由、试仓阶段、入场回合、持仓期间峰值、保护价、估值区间和复核回合。逆势不无限摊平，趋势型保持有效趋势，退出计划在未卖完时继续执行。
- `guess_stock_ai_decisions` 分开保存计划和成交，按订单 ID 关联。在清算前，实际成交量为 0；成交、部分成交、未成交、撤单和被后续计划替代分别记录状态，成交敞口用真实成交价、现金和费用计算。历史审计不猜测回填。
- 默认每 24 回合模型复核，重要变化最短间隔 8 回合；普通波动、重复事件、观点到期或普通财报不再逐阶段重复请求。贷款预警、到期、保护价和观点失效由本地即时处理，不必等待付费模型。旧观点失效且没有有效模型替换时执行退出，而非沿用失效观点加仓。
- `FAST/STRONG` 使用同一已配置模型，分别为 8/12 秒超时，不再因低置信度或结构错误对相同快照追加付费调用；错误交给本地计划处理。已开始的后台决策有最多 28 秒清算宽限，清算兜底不启动新的 HTTP 请求，也不能重复执行后台已经领取的任务。
- 模型收到的买卖冲击成本按单笔步长、剩余换手、可用资金/持仓及冲击预算估算，不再把配置最大下单股数当作必然成交量。决策包显式列出当前观点允许的短动作，并区分上次模型目标、本地战术建议与硬敞口上限，避免因格式歧义浪费已付费响应。
- 中性目标 0 只约束模型复核所在回合；后续新回合出现覆盖成本的公开机会时，本地可重新评估，不能把一次观望永久当成禁买上限。正数模型仓位预算仍有效；明确看空或关闭观点的 0 目标通过持久化 `modelEntryBlocked` 保留禁买约束。保护价、信用风控和未完成退出仍优先，不因新机会跳过卖出。
- AI 任务缓存键包含场次、AI、回合、阶段、快照版本、提示版本、观点版本和模型路线。相同上下文可复用已验证的模型结果，包括暂停导致取消但已完成的模型响应；不把本地降级结果当作供应商结果。JSON mode 能力按接口地址和模型缓存，只对明确不支持 `response_format` 的 400 做一次兼容重试，不对无关错误盲重试。
- AI 对手数量不设固定业务上限；执行器仍使用 4～8 个工作线程并通过队列背压保护模型服务和数据库。AI 越多，模型费用、阶段完成耗时和订单流影响越高。定时任务不再用一个全局事务顺序等待全部 AI；同批到期任务先用短事务原子领取，再并行处理。模型 HTTP 通过 `NOT_SUPPORTED` 网关挂起数据库事务，返回后才按“场次→参与者”顺序加锁并提交，因此等待模型时没有活动数据库事务，也不持有任务、场次或持仓行锁。`PROCESSING` 超过 30 秒会自动恢复为待执行。后续仍可把多个 AI 结果合并成单次批量提交。
- 风格原有仓位、持有期、冷却和换手上限继续有效。`TARGET_AUCTION` 的 AI 每阶段均可增减仓，旧分阶段模式保持“开盘买、收盘卖”。竞价订单携带允许方向、最大股数、剩余换手金额及价格区间，最终清算不能绕过前置约束；风险退出可以处理低于普通最小金额的尾仓，但不突破换手等硬上限。
- 同回合普通反向交易继续被拦截；结构化失效、保护价、退出计划或信用风险等服务器确认的退出可以绕过持有/反向冷却，但不改变旧模式的阶段方向权限。最后一回合不会仅因游戏结束而生成普通 AI 卖单；有贷款仍按信用规则清偿，计划强平量只参与一次收盘定价。
- `riskPercent` 字段为兼容旧配置继续表示最大总仓位。`activityPercent` 改为传给 Agent 的交易活跃倾向，不再执行随机跳过，避免同一事实下由随机门控造成断续行为。
- 多人使用 6 位邀请码，2～8 名真人，允许游客。事件确认、阶段结算、收盘结果和重新开始均等待全部有效真人。
- 单人场次和多人房间分别保存：同一玩家可以保留一个进行中的多人房间，同时开始或继续自己的单人场次；游戏详情分别提供“继续游戏”和“返回多人房间”入口，二者互不覆盖。
- 返回游戏详情不会退出多人房间。多人房间只剩 1 名有效成员时继续保留，但人数不足 2 人不能开局；只有最后一名成员主动离开时才自动关闭空房间。
- 房主可以在房间大厅或多人对局页手动关闭房间。关闭只会终止该房间关联的多人场次并使全部成员返回游戏详情，不会改变任何成员的单人进度。
- 断线满 60 秒后房主可移除成员；不提供房主强制跳过有效成员。
- 自动交易截止后有 800ms 订单排空保护；同节点内已经进入服务端的提交/修改/撤销操作全部完成后才清算。当前运行时计数适用于单节点部署，多节点部署需改为 Redis/数据库共享屏障。

- 不改变已保存的模型和密钥。直连 DeepSeek 时显式关闭默认思考模式，默认 `max_tokens=384`。优先输出短 JSON，例如 `{"a":"C","x":35,"c":0.8,"d":"B","sl":90,"r":"超跌试仓"}`，服务端兼容并还原旧完整协议。

## 银行融资与信用风险 V1

- 新游戏可按版本配置开启贷款；没有字段的旧版本归一化为关闭，因此旧场次价格、AI 和排名行为不变。系统硬限制最大股票敞口 300%、最大债务/净资产 200%。
- 默认提供稳健、进取、高风险三档银行，实验性极端银行默认关闭。产品配置包含初始资金额度、债务/净资产、最大敞口、每回合简单利率、期限、最低借款、冷却、抵押折扣、放款/警戒/禁借/强平/恢复 LTV。保存时严格验证 `origination < warning < block < liquidation` 且 `recovery < warning`。
- 每个参与者在每家银行拥有独立授信账户，每次放款生成独立 tranche 和到期回合；可以同时向多家银行借款和分别还款，但额度、LTV、股票敞口和强平始终按全部银行债务合并计算。请求使用 `requestId` 幂等，并在场次、参与者和授信账户上使用行锁防止并发超借。
- 统一口径为 `净资产 = 现金 + 股票市值 - 本金 - 未付利息`、`Exposure = 股票市值 / 净资产`、`LTV = 有效债务 / (现金 + 股票市值 × (1 - 抵押折扣))`。场内资产、收益率排名和最终结算均使用净资产，允许违约后的负资产和低于 -100% 的收益率。
- 每回合先进入 `ROUND_START`，Web 完整播放新回合提示后自动确认；单人无客户端时有 6 秒服务端兜底，多人等待所有有效真人完成提示。`PHASED` 严格按“开盘事件（有则显示）→ `CREDIT_TRADING` 独立贷款阶段 → 开盘交易 → 开盘结果 → 新的收盘事件（有则显示）→ 收盘交易 → 收盘结果 → 必要时 `CREDIT_REPAYMENT`”推进；`INLINE` 不创建 `CREDIT_TRADING`，融资和开盘下单在同一交易阶段完成并共用 `tradingSeconds`。
- 只有 `PHASED` 使用 `creditPhaseTimed/creditPhaseSeconds`，贷款倒计时范围 3～600 秒；`INLINE` 的贷款阶段计时配置会被关闭，手动推进时融资与交易共同等待确认。两种模式都保留 `repaymentPhaseTimed/repaymentPhaseSeconds`。没有真人未结清贷款时直接跳过还贷；`INLINE` 还会在非最终回合、贷款未到期且风险为 SAFE 时跳过还贷弹窗，仅在最终回合、到期或风险需要处理时打断玩家。主动还款允许场次进行中的其他操作阶段，先付利息再按最早到期本金清偿；买单冻结现金不能用于还款。借款当回合收盘计息，到期和最后一回合先扣现金，再以收盘价卖股；维护性强平使用二分规划最少股数恢复到目标 LTV，资不抵债进入 `DEFAULTED`。
- 每笔计息流水的现金变化为 0，因为利息进入未付利息而非立即扣款；Web 改为显示 `interestDelta`。全部贷款按合同 ID 倒序（最新优先）每页 3 条，并在弹窗生命周期内保留所选页。仍有本息时锁定当前银行，全部还清后重新返回所有启用银行的可选额度。
- 收盘前先以开盘参考价计算所有预计强平量，将预计强平卖盘和普通卖盘一起送入一次 `MarketPriceEngine`；最终收盘价形成后统一成交和偿债。最终价格导致的额外处置按同一最终价完成，不再递归定价，避免清算死亡循环。
- AI 输出升级为 `target_exposure_pct`（兼容读取旧 `target_position_pct`），模型不决定银行和贷款金额。后端执行 Persona 最大敞口、15/30pp 加仓步长、30/60pp 主动降杠杆步长、最低成本银行路由、授信额度和 LTV 限制。多家银行可以同时持有独立贷款，目标降至 100% 以下后，收盘卖出现金自动按贷款顺序还债。
- V38 创建授信账户、贷款合同、贷款流水和逐回合信用快照。流水覆盖借款、计息、主动/自动还款、到期/风险强平和违约；快照记录净资产、抵押品、债务、敞口、LTV、状态和强平股数。
- V39 增加逻辑版本标识、游玩密钥及使用流水，并为贷款合同增加原到期回合与延期统计字段。每笔贷款最多延期 2 次，单次可选回合数与所属银行的贷款期限范围一致，例如贷款期限上限为 10 回合时，延期可选择 1～10 回合。
- V40 将授信账户调整为按“场次 + 参与者 + 银行产品”唯一，使每家银行独立维护合同与流水；全局额度、LTV、敞口和强平仍合并全部银行债务计算。

### 融资参数说明与建议

| 参数 | 作用 | 建议设置 |
| --- | --- | --- |
| 启用银行 | 决定玩家和 AI 能否选择该产品 | 新手开启稳健/进取，标准可加高风险，极端默认关闭 |
| 初始资金额度 | 本金相对初始资金的绝对上限 | 稳健 30%～60%，进取 70%～110%，高风险 120%～160%，硬上限 200% |
| 债务/净资产 | 随实时净资产变化的动态本金上限 | 稳健 30%～60%，进取 70%～110%，高风险 120%～160%；一般不明显高于初始资金额度 |
| 最大股票敞口 | 股票市值/净资产的硬上限，100% 表示不能靠贷款扩大仓位 | 新手 130%～160%，标准进取 180%～210%，高风险 220%～260%，极端 280%～300% |
| 每回合利率 | 每个收盘按未偿本金计收简单利息，借款当回合计息 | 稳健 0.2%～0.5%，进取 0.6%～1.0%，高风险 1.0%～1.5%，极端 1.5%～2.2% |
| 贷款期限 | 每笔 tranche 从放款回合起独立计算到期 | 长局/新手 3～5 回合，高风险短局 2～3 回合；非极速挑战不建议 1 |
| 最低借款 | 单笔最低金额占初始资金比例，过滤碎片贷款 | 标准 5%，高风险 10%，0 仅用于沙盒 |
| 借款冷却 | 成功借款后再次借款需要等待的回合数 | 标准 1，稳健 2，0 仅用于快速杠杆沙盒 |
| 股票抵押折扣 | 计算抵押价值时扣除股票市值的比例；越高则额度越低、LTV 越高 | 稳健 3%～6%，进取 6%～9%，高风险 8%～12%，极端 10%～15% |
| 放款 LTV | 新增贷款后的最高允许 LTV | 比警戒低 4～8pp；默认四档 36%/56%/66%/75% |
| 警戒 LTV | 进入 WARNING 的提前提示线 | 比放款高 4～10pp |
| 禁借 LTV | 禁止新增贷款和提高敞口的控制线 | 比警戒高 3～5pp |
| 强平 LTV | 触发系统卖股恢复风险的处置线 | 比禁借高 3～8pp，间距过窄会频繁强平 |
| 恢复 LTV | 强平完成后希望回到的目标；越低卖股越多 | 比警戒低 4～10pp |

配置必须满足 `放款 < 警戒 < 禁借 < 强平` 且 `恢复 < 警戒`。推荐按“目标最大敞口 → 两项本金上限 → LTV 阶梯 → 利率和期限 → 最低借款与冷却”的顺序设置。实际额度取初始资金上限、净资产上限和放款 LTV 余量的最小值；最大敞口通常不应明显高于 `100% + 债务/净资产上限`。不要同时配置高敞口、低利率、长期限和宽松 LTV，否则杠杆接近免费且容易破坏排名与价格平衡。

| 最大预估冲击 | 预计价格冲击过大时缩量 | 稳健 1%～2%，标准 2%～4%，高于 5% 仅用于极端玩法 |
| 普通/强信号步长 | 一次决策可移动的目标敞口 | 默认 15/30pp；稳健 5～10/15～20pp；激进 20～30/40～60pp |
| 反向交易冷却 | 限制买卖方向在相邻回合反复切换 | 默认 2，稳健 3～5，灵活 1～2，0 仅用于高频测试 |
| 自定义投资理念 | 描述证据偏好、风险纪律和持仓方式，不可突破服务端风控 | 写 1～3 条短而可执行的原则，不要求固定股数或隐藏信息 |

AI 参数可以不逐项填写：选择风格时 Web 会同步带入完整默认值。通常先调整最大敞口、调仓缓冲和交易活跃度，运行数局后再微调步长、换手和冲击限制，不建议一次放宽全部边界。

## Web 交互验收

- 顶部同时显示当前价格、收益率、现金、持仓和总资产。
- 买卖操作栏按阶段使用明确的绿色买入和红色卖出状态头，直接显示“当前操作：买入/卖出”，倒计时截止后显示“本阶段已截止”。
- 长局走势图默认选择“1 回合”，逐回合展示所有已经完成的回合；切换到“2/3/5/10 回合”时，按时间顺序把每段连续的对应回合合并为一根价格柱，而不是只查看最近若干回合。合并柱以组内第一回合开盘价为开、最后一个已完成回合收盘价为收；事件名称、订单流影响以及玩家买卖数量在组内汇总，成交价显示为按成交股数加权的均价。未满一组时也展示当前已完成部分。
- 买入快捷操作包含 25%、50%、75%、100% 和“全部”；“全部”按实际开盘价使用全部可用现金，界面会明确区分它和受单次上限约束的 100%。
- 创建/编辑游戏时，随机事件通过弹窗新增和修改；AI 阵容按对手逐项配置，不再只配置统一数量和风格。
- “添加 AI”使用风格选择弹窗；选择稳健、趋势、逆势、激进或灵活时，名称、资金、单次下单上限、活跃度、风险仓位和策略说明同步切换，保存前仍可微调。
- 单人自动模式顶部提供五档倍速和可关闭的自动进入下一阶段开关；设置通过场次接口保存，刷新或换设备同步场次状态，本地只保存下次开局偏好。
- 开启贷款的场次每回合新增银行贷款期和收盘后的银行还贷期并自动弹出银行页；两阶段默认不限时并等待所有真人完成，可由创建者分别开启倒计时。没有任何真人未结清贷款时自动跳过还贷期。顶部银行按钮置于阶段弹窗之上，存在债务时可在任意进行中阶段打开并主动还款；已结清合同继续显示原借款与已还本金。
- 场内与版本排行榜均按收益率降序，收益率相同时再按资产排序。
- 买卖股数输入采用短延迟自动保存，百分比和“全部”按钮立即保存订单，不再需要二次点击提交；收盘阶段“全部”提交全部可卖持仓。输入 0 会撤销当前订单。
- 收益率排名同时展示每位参与者的持仓股数、可用资金、收益率和实时总资产。
- 开盘、收盘阶段结算弹窗可按回车确认；所有弹窗支持进入和离开过渡，阶段弹窗采用较轻的回合切换动效。
- 娱乐广场、游戏详情和游玩页共用完整说明书弹窗，覆盖快速上手、四种游玩方式、创建游戏、AI 配置与策略、价格公式和参数解释。
- 创建者只能删除已下架游戏，删除采用不可见软删除以保留已有场次和排行榜的数据完整性；玩家可单独隐藏自己的游玩记录，公共排行榜成绩不受影响，进行中的多人记录需先完成或关闭房间。
- 事件详情在价格结算前只显示事件名称、说明和公开元数据；方向、影响层级、市场状态、原始/最终变化、适配比例和原因由后端响应一并隐藏，避免只靠前端遮挡结果。
- 走势图固定完整回合横轴；仅在收盘生成后把同回合开盘和收盘合并为一根细 K 线式矩形价格柱，不提前绘制当前回合。相邻回合使用一条直线连接两个矩形的中心点，连接线先绘制、价格柱后绘制，确保线处在矩形下层；连接上涨为绿线、下跌为红线。收高于开为绿柱、收低于开为红柱，柱体无圆角和白色节点。悬停窗口偏离当前柱显示，不遮挡价格柱，并展示开收盘、事件、订单影响及个人买卖成交。
- 弹窗、阶段提示均带进入过渡；进入新回合时用整页横幅过渡。暂停继续弹窗拥有最高展示优先级，不与事件或结算弹窗重叠。
- 多人房间关闭按钮位于弹窗遮罩之上；规则或阶段弹窗打开时，房主仍可直接发起关闭，并使用独立确认层完成操作。
- 节点默认小且稀疏，悬停平滑放大；提示包含阶段价格、涨跌、事件、订单影响和当前玩家成交。
- 只有当前玩家实际成交的回合才显示贯穿该回合的交易虚线：绿色表示买入，红色表示卖出；同回合同时有买卖时在该回合中心线上交替显示两种颜色，不再使用三角图标，也不会把 AI 或无成交回合误标为当前玩家成交。
- 手机浏览器中交易面板紧接在走势图下方，走势图最小高度 245px，不直接压缩桌面图。
- 规则按钮集中展示买卖规则和计算公式，盘面不重复堆放说明文字。
- 可恢复的整页加载失败继续使用空状态；点击开始、继续、重开、保存、发布、密钥、房间、贷款、研究和交易等操作失败时，统一使用挂载到 `body` 的顶部提示弹窗，不在内容区域插入横幅或挤动布局。提示层级高于说明书、银行页和确认框，并提供关闭按钮。
- HTTP 401/403/404/409/429 和网络超时显示可执行的中文原因；HTTP 5xx、业务 5xx、`status code 500`、SQL 异常和内部服务错误统一转换为“服务暂时无法完成该操作，请稍后重试”，页面不向玩家暴露状态码、堆栈或数据库信息。

## 仍需确认的边界

1. 订单排空的运行时计数不是跨节点共享状态；正式多实例部署前需明确采用 Redis 分布式计数、数据库提交状态还是 WebSocket 客户端提交屏障。
2. 尚未配置跨供应商自动重试和备用模型；模型失败时按活动观点连续性降级。模型预算已有遥测基础，正式按游戏的日预算、玩家配额和费用告警仍需运营规则。
3. 当前行情是玩法内模拟市场，不对接真实股票代码、交易日、涨跌停、税费和最小交易单位。
4. 不同 AI 初始资金不会直接抬高收益率排名，但仍会影响绝对下单规模和市场冲击；收益率相同才比较最终资产。
5. “全部”只购买整数股，成交后不足一股的余额保留为可用现金，不会产生碎股或负现金。
