手机端预开发清单（基于 2026-07-21 Web 与 Flutter 顾客端差异盘点）

说明
1. 本文只记录尚未在 customer_frontend（Flutter）完整实现的能力，不重复列出已经具备的动态信息流、推荐/相关页签、动态搜索、话题、草稿、点赞、表情回应、评论/回复、动态隐私、聊天内分享和消息未读数等功能。
2. 后端已经为引用与 @ 提及预留统一数据结构和接口。手机端接入时应直接复用接口字段，不要在客户端解析正文来推断引用或被提及用户。

P0：本次新增能力的手机端接入

一、引用动态与引用评论
- Moment 模型解析 quote：type、momentId、commentId、author、momentTitle、content、createdAt、available、unavailableReason。
- 动态卡片和动态详情在正文下方渲染引用卡片。
- 动态引用卡片展示标题、作者头像/昵称、发布时间和三行省略正文。
- 评论引用卡片展示评论作者头像/昵称、发布时间、评论内容，并在底部弱化展示来源动态标题。
- 动态右上角菜单对本人和他人的可见动态都提供“引用动态”。
- 评论及回复的右上角菜单提供“引用评论”。
- 发布页增加可见动态搜索和单选引用模块；一条动态只能引用一个动态或一条评论。
- 发布/编辑请求接入 quotedMomentId、quotedCommentId；编辑已有引用时保留 quote 快照。
- 点击引用卡片进入来源动态，并在引用评论场景定位 commentId。
- 来源动态后续改为无权限时，引用卡片仍显示快照；进入详情后展示“该动态已被设置权限，无法查看详情”。
- 适配草稿、编辑、删除来源内容、分页中定位深层回复等边界场景。

二、动态与评论 @ 用户
- 发布动态正文输入 @ 时打开用户选择弹窗。
- 评论/回复输入 @ 时打开同一用户选择弹窗。
- 弹窗默认展示最近直接聊天用户，并支持按昵称搜索所有可用用户（含顾客与商家）。
- 支持连续选择任意数量用户、去重、删除正文中的 @ 后同步移除对应 mentionedUserIds。
- 发布/编辑动态请求接入 mentionedUserIds；评论/回复请求也接入 mentionedUserIds。
- Moment、MomentComment 模型解析 mentions，编辑时恢复已选择用户。
- 正文与评论中的 @昵称 使用加粗暖橙色；悬停/长按展示用户资料卡（头像、昵称、角色，以及按用户隐私权限决定是否展示的电话等资料），点击进入该用户的动态主页。提及当前登录用户时标注“自己”、展示本人完整资料，并进入自己的动态管理页。
- 处理同名、用户停用、搜索无结果、快速连续输入和光标中间插入等情况。

三、动态通知跳转与新通知类型
- 消息中心识别 MOMENT_LIKED、MOMENT_COMMENTED、MOMENT_REACTED、MOMENT_MENTIONED、MOMENT_COMMENT_MENTIONED、MOMENT_COMMENT_REPLIED、MOMENT_QUOTED、MOMENT_COMMENT_QUOTED。
- 完整展示服务端 content，不在手机端重新拼接通知文案。
- 点击通知先标记已读，再从 payload 读取 momentId、commentId，进入动态详情并定位评论。
- 引用来源或动态权限变化时，在目标页展示受限状态，不停留在空白页。
- 为动态互动、@、引用配置可辨识的通知图标，并保留现有 WebSocket 实时刷新和总未读徽标。
- 验证前台、后台恢复、推送点击冷启动三种入口的深链行为一致。

P1：此前 Web 已有、手机端尚未完整对齐的能力

四、评论多图
- Flutter 当前每条评论只支持一张 imageUrl；对齐 Web 为最多 6 张 imageUrls。
- 增加多选、横向预览、单张删除、失败重试、上传中禁发和图片九宫格查看。
- 兼容历史正文中遗留的评论图片 URL。

五、动态与评论的外部分享模式
- Flutter 当前主要支持分享到站内聊天；补齐“分享到其他应用”。
- 支持“可继续浏览动态列表”和“仅查看当前动态”两种分享范围。
- 评论外部分享应携带 commentId，落地后定位对应评论。
- 对接系统分享面板、Web 分享卡片 URL、冷启动/热启动深链与权限失效页。
- 接入分享统计字段 shareCount、appShareCount、externalShareCount；站内分享仅在聊天消息成功发送后计数，站外分享仅在系统分享面板确认完成后上报，打开面板、取消分享或仅复制链接不得计数。

六、动态图片上传体验
- 对齐 Web 的选择后本地预览、统一上传、逐张状态、失败保留与单张重试。
- 发布已成功但部分图片失败时，不丢失动态和待重试图片。
- 草稿与已发布动态编辑均需正确合并已有远端图片和本地待上传图片。

七、通知与列表细节对齐
- 消息中心点击普通业务通知目前主要执行已读，需统一补齐订单、反馈、家庭、聊天和动态的 payload 路由。
- 通知列表、首页入口和系统推送的未读数必须共享同一刷新结果，处理全部已读后的即时归零。
- 超长通知、评论和回复统一使用省略号规则，同时保留进入详情查看完整内容的能力。
- 未读口径与顾客端主壳保持一致：聊天总徽标排除已静音会话，单会话仍展示自身未读状态；通知以 readAt 是否为空为准，动态“相关”未读继续使用服务端阅读记录。
- “相关”动态页签直接显示 relatedUnreadCount 徽标；仅当相关列表中的未读动态卡片实际进入可视区域时批量调用已读接口，推荐列表和后台隐藏的动态页不消费未读，口径与 Flutter 现有实现一致。
- 聊天、通知、动态新内容及已读变化统一由 /ws/customer 的 CHAT、NOTIFICATION、MOMENT 模块实时驱动，接口轮询只保留低频兜底；断线重连后立即全量校准徽标。
- 所有相关导航栏、页签、消息中心入口和会话项同步显示徽标，收到消息、进入阅读、单条已读和全部已读后即时更新。
- 推荐与相关页签分别保存切换前一刻的列表、分页和滚动位置；在动态与聊天之间切换时，同时保留当前动态页签及该页签的最后浏览位置，返回后恢复而不是共用一份滚动位置。

八、展示样式与时间规则
- 引用动态/评论卡片使用白色背景，仅以弱化的左侧细线轻量分隔并与动态正文自然融合；不使用明显的上下分隔线、强调色边框、灰底或多余类型标签。
- 引用动态正文以纯文本最多展示 3 行，引用评论以纯文本最多展示 2 行，不保留正文富文本格式。
- 信息流动态卡片中的评论预览不显示“热门评论”和“x条评论”，使用更紧凑的内外边距和协调的正文字号。
- 信息流动态卡片中的评论预览同时展示评论发布时间，并复用统一的相对时间与具体时分规则。
- 信息流动态卡片仅在 rootCommentCount（直接评论数）至少为 2 时显示“展开更多评论”，回复数不得参与判断；按页无感追加其余评论并使用过渡动画，加载过程中保留当前评论且显示评论列表骨架，避免内容闪烁或整块刷新。展开状态始终提供“收起评论”，两个操作保持相同的水平起点，收起后恢复仅展示一条评论。
- 动态、评论、引用卡片、通知和会话列表复用同一相对时间规则。
- 不满 1 分钟显示“刚刚”，不满 1 小时显示“x分钟前”，不满 24 小时显示“x小时前”。
- 超过 24 小时但仍属于本地日历昨天时显示“昨天 HH:mm”；其余时间显示具体时分，当年使用 MM-DD HH:mm，跨年使用 YYYY-MM-DD HH:mm。
- 动态评论下的回复采用与评论一致的头像、昵称、发布时间、正文、图片和操作布局，并支持独立点赞；同一评论线程内按 createdAt、id 从早到晚稳定排序。
- 所有三点操作菜单打开后都要按实际尺寸校验视口边界：下方不足时显示在触发按钮上方，右侧或左侧不足时切换对齐方向，并使用顶层浮层避免被列表、卡片或滚动容器裁剪遮挡。
- 三点操作菜单不得使用会拦截页面滑动的全屏透明层；菜单打开后页面仍可正常滚动，开始滚动或点击菜单外任意位置时自动关闭。
- 热门话题、搜索话题、搜索引用动态、搜索提及用户、聊天用户搜索及其他异步列表在等待数据时展示与结果形态对应的骨架加载，不以纯文字“加载中”替代。

接口字段备忘
- 创建/编辑动态：quotedMomentId、quotedCommentId、mentionedUserIds。
- 创建评论/回复：mentionedUserIds。
- 动态响应：quote、mentions、rootCommentCount（仅直接评论数；commentCount 继续表示全部评论及回复数）。
- 动态响应分享统计：shareCount、appShareCount、externalShareCount。
- 评论响应：mentions。
- 引用评论详情：GET /api/moments/{momentId}/comments/{commentId}。
- @ 用户搜索：GET /api/moments/mention-users?query=xxx。
- @ 用户资料卡：GET /api/moments/users/{userId}/card（电话等敏感字段由服务端权限字段控制）。
- 外部分享完成上报：POST /api/moments/{momentId}/external-shares，仅在系统分享成功回调后调用。
- 通知 payload：至少读取 momentId、commentId、conversationId、orderId。

建议验收顺序
1. 先完成模型与 API 兼容，确保旧版本忽略新字段时不崩溃。
2. 完成引用卡片、引用入口和权限失效页。
3. 完成 @ 选择、光标插入和通知跳转。
4. 补齐评论多图与外部分享。
5. 最后覆盖 Android/iOS 的推送深链、弱网重试、草稿恢复和回归测试。

P0：必须接入

一、动态页“热门”栏
- 在“推荐”旁新增“热门”页签，展示服务端返回的前 10 条热门动态。
- 热门排序完全采用服务端结果：综合互动热度与发布时间；客户端不得自行重排。
- 支持加载、空状态、失败重试、下拉刷新，并保留推荐/热门/相关各自的列表与滚动位置。
- 热门动态卡片继续复用现有点赞、回应、评论、分享、引用、权限受限和删除后的状态处理。
- 通过 WebSocket 收到动态变更后按服务端约定刷新热门列表，不依赖客户端直接修改排名。

二、Feed 与动态基础数据批量接口对接
- Feed、话题页和个人动态页只消费服务端返回的完整响应，不感知 Redis ID 列表与 MGET 实现。
- 验证翻页无重复、无漏项，删除/改权限/拉黑/不看 Ta 后刷新不会继续展示不可见动态。
- Redis 不可用时后端降级 MySQL，手机端应保持同样的加载、分页和错误提示行为。

三、动态未读数
- “相关”页签及动态入口继续展示服务端 relatedUnreadCount，不在本地推算。
- 标记已读、发布相关动态、用户关系或隐私变化后及时重新拉取；WebSocket 仅触发刷新。
- 覆盖断线重连、后台恢复、重复已读、批量已读和 Redis 降级场景。

四、热门话题
- 话题入口使用服务端热门话题排序和数量；搜索话题仍使用搜索接口，不混用热门结果。
- 验证创建动态、编辑话题、删除动态后的榜单变化，以及榜单为空与 Redis 降级场景。

P1：列表与互动缓存对接验收

五、话题动态列表与个人动态列表
- 复用现有话题和用户动态分页接口，确认缓存命中与数据库降级的响应结构完全一致。
- 个人动态需覆盖本人草稿/已发布与访问他人主页的权限差异；草稿不得混入公开缓存列表。
- 发布、编辑、删除、隐私调整后刷新列表，确保旧条目不会残留。

六、评论首屏与热门评论
- 动态卡片热门评论及详情评论第一页复用服务端结果，评论回复仍按稳定顺序分页。
- 新增、删除、点赞评论后刷新首屏和热门评论；处理评论已删除、被屏蔽与权限变化。
- 覆盖多图评论、深层回复定位、弱网重试和 Redis 降级。

七、互动计数器
- 点赞数、评论数、分享数、各表情回应数以接口响应为准，禁止客户端基于多次点击永久累加。
- 乐观更新失败时回滚；重连、刷新和跨设备操作后以服务端数据校准。
- 覆盖重复请求、快速取消、并发互动、站内/站外分享统计和数据对账后的 UI 校准。

- 推荐与相关动态首屏及分页数量调整为每页 12 条，热门仍采用服务端返回的前 10 条。
- 分页追加时按动态 ID 去重，避免服务端数据变化造成重复卡片。
- 动态图片、引用图片、评论图片与非首屏头像使用懒加载和异步解码；图片容器保留固定尺寸，避免加载后布局跳动。

- 验证连续快速切换推荐/热门/相关时，请求结果不会写入错误页签。
- 验证分页失败不会无限请求，恢复网络后点击重试只追加一次且无重复动态。
- 验证多图动态、热门评论和引用卡片进入可视区域后再加载图片，滚动位置不发生明显跳动。

- 开盘前已经发生的事件进入收盘前时不再弹窗；沿用已公开方向，只重新判断是否影响收盘价，并在影响时重新生成幅度。

P0：事件与市场状态衔接
- 创建/编辑事件增加需求、供给、政策、财务、突发、行业、情绪类型，以及相关度、可信度、意外程度、事件强度选择；CSV 导入导出保持与 Web 字段一致。

- 复用服务端上涨、下跌、震荡、过热、超卖、高波动识别结果。相同事件在不同市场状态中允许被放大或吸收，最终影响同时受基础波动率上限约束。

P0：订单、结算与排名交互
- 股数输入结束后短延迟自动保存，比例和“全部”按钮立即保存；输入 0 撤单，收盘“全部”卖出全部可卖持仓。

P0：AI 双阶段策略
- 复用服务端自主 Agent 的目标股票敞口决策，不在手机端判断市场状态、计算敞口或覆盖 AI 订单；展示时兼容市场状态、方向、目标敞口、信心、周期、理由和失效条件。

- 回归覆盖不同 Persona 对同一行情产生不同目标敞口、结构化 Thesis 生命周期、失效条件验证、调仓缓冲、同回合反向保护、模型不可用时沿用活动观点，以及最后回合按最终价自动资产折算。
- 手机端 AI 配置后续增加调仓缓冲、最短持有回合、最小交易资产占比、单回合换手上限和最大预估价格冲击；说明书同步展示 CREATE/KEEP/ADJUST/REPLACE/CLOSE 观点流程。

P0：银行融资与杠杆（本轮仅 Web 与后端实现，手机端暂不开发）

- 游玩页增加融资入口、产品选择、借款/还款模式、比例快捷键、净资产/本金/利息/敞口/LTV、警戒/禁借/强平刻度、最近贷款流水和到期回合。
- 所有资产和收益率展示必须扣除本金与未付利息；支持 NORMAL、WARNING、BLOCKED、LIQUIDATION、DEFAULTED，违约资产允许为负数。
- 走势图显示强平竖线和聚合强平数量；收盘结果区分普通卖出与强制卖出。客户端不计算额度、利息、LTV、强平股数或 AI 借款，完全展示服务端权威结果。
- AI 展示字段从目标仓位改称目标股票敞口，范围 0%～300%；100%以上由后端自动选择最低成本可用银行，已有债务期间不自动换行，降至 100% 以下后卖出现金优先还债。

原生端新增回归清单

- 验证单人自动开关、五档速度、偏好恢复、暂停恢复、最终结算及多人不显示自动控件。
- 验证不同初始资金参与者按收益率排名，而不是按资产绝对值排名。
- 验证开盘前、开盘结果、收盘前、收盘结果四个阶段的事件信息披露边界。
- 验证长局走势图支持 1、2、3、5、10 回合粒度：“1 回合”逐回合展示，其余档位将每 N 个连续回合合并为一组（含末尾未满组、事件/订单/个人成交汇总和成交加权均价）；验证移动端横向布局与倒计时归零后所有订单控件同步锁定。

2026-08-31：娱乐股票模块 Web/后端已完成能力的手机端最终待开发清单

说明
1. 本节汇总 2026-08-29 之后 Web 与后端继续完成、但 customer_frontend（Flutter）仍未实现的全部娱乐股票能力；如与前文存在冲突，以本节为准。
2. 手机端只负责输入、展示和阶段交互。市场价格、事件抽取与传导、AI 决策、贷款额度、计息、到期、强平、排名、阶段跳转及幂等性均以后端响应为唯一事实来源。
3. 原生端不得复制 Web 的计算公式来预测结果；恢复游戏、弱网重试和重复点击时必须继续使用服务端 sessionId、phase、serverTime、phaseEndsAt 和 requestId/clientRequestId。
4. 优先复用 Web 的中文文案和游戏说明，但布局需按手机屏幕重新设计，不直接照搬桌面双栏或宽表格。

P0：入口、创建与访问控制

一、娱乐股票入口与多人游戏
- 娱乐股票首屏直接提供可游玩的游戏列表、创建入口、历史记录和说明书，不制作额外营销落地页。
- “多人游戏”保持一个主按钮；点击后用弹窗收集邀请码、游玩密钥、AI 使用方式等信息，再确认进入房间。
- 多人房间展示成员头像、名称、房主、AI 凭证是否就绪、当前阶段已完成/未完成、重开确认等状态。
- 房主关闭房间、全部玩家确认重开、成员离开、断线重连和后台恢复时，手机端必须重新同步服务端房间与场次状态。

二、版本与排行榜分组
- 创建者可填写版本标识。编辑并重新发布时，如果版本标识文本未改变，即使其他配置发生变化，成绩仍归入原版本标识对应的排行榜；只有修改版本标识才开启新的排行榜分组。
- 游戏详情、历史记录和排行榜需同时展示技术版本号与作者版本标识，禁止仅用本地发布时间推断版本。
- 排行榜按收益率排序；场内列表还要展示每位参与者的持仓股数、可用资金、净资产及当前收益率。

三、游玩密钥
- 创建者可设置游戏是否需要游玩密钥，并配置密钥适用范围为单人、多人或两者。
- 支持单次、多次（指定最大次数）和无限次密钥；创建者可新增、删除、禁用密钥，并查看掩码、已用次数、剩余状态、最后使用时间和当前状态。
- 已删除或已禁用密钥不可使用；达到次数上限后服务端拒绝进入。手机端只展示服务端错误，不在本地预扣次数。
- 开始单人游戏和进入多人房间均需在真正创建场次前提交密钥，避免先创建无效场次。

四、游戏与游玩记录删除
- “我的游戏”允许删除已下架游戏，删除前弹出明确确认窗口。
- 历史记录允许删除单个个人游玩记录，删除前确认；个人入口删除不影响其他玩家及已产生的公共排行榜成绩。
- 删除、下架、权限改变后返回列表应立即移除对应条目，并处理详情页已打开时的失效状态。

P0：编辑器与通用组件

五、编辑器标签与分页
- 游戏编辑器按“基础与市场、AI 对手、银行融资、事件池、版本与密钥”拆分标签，不把长表单堆在一个滚动页。
- 事件池在编辑页和游戏介绍页均分页；AI 对手每页显示 2 个；银行融资编辑页不分页。
- 分页组件需有当前页、上一页、下一页、总数和小屏省略策略；选中页按下/悬停时不能出现白底白字。
- 所有枚举下拉框统一使用原生端设计系统 Select；弹层必须位于顶层 Overlay，避免被父容器、滚动区或底部面板裁切。

六、AI 添加与模型配置
- “添加 AI”使用弹窗，先选择稳健、趋势、逆势、激进、灵活风格，再联动名称、初始资金、单次下单上限、交易活跃度、风险仓位上限、最短持有期、调仓缓冲、换手上限、最小交易资产占比、价格冲击上限和策略说明。
- AI 数量不设 8 个的业务上限；编辑和游玩页面均使用分页或虚拟列表，避免一次渲染大量 AI。
- AI 参数允许留空时采用后端/风格默认值；手机端应标注默认值、作用、建议区间，不得把空值自动保存为 0。
- 模型提供商下拉需保留 DeepSeek 等预设身份。修改预设地址、模型名或其他字段后，不要仅因为值发生变化就立刻把选择显示成“自定义”；只有真正不匹配任何预设时才显示自定义。
- 创建者配置游戏默认 AI Key 后，玩家开始游戏时仍可选择使用作者配置、使用自己的 Base URL/模型/API Key，或在允许时不启用 AI。
- 玩家自己的 API Key 只用于当前玩家授权的场次，界面不得回显完整密钥，也不得写入普通本地日志。
- 娱乐 AI 请求不得沿用通用 15000ms 超时；采用非阻塞等待、服务端任务轮询/推送和可恢复状态，页面离开后重新进入仍能继续读取任务结果。

七、事件 CSV
- CSV 模板包含 EVENT 示例行和 GUIDE 说明行，逐字段说明 rowType、名称、描述、方向、发生概率、生效概率、最小/最大影响、类型、相关度、可信度、意外程度、强度、启用状态。
- GUIDE 同时给出理论建议区间和典型参数值；导入时忽略 GUIDE 行，兼容旧模板缺少 rowType 和新增元数据字段的情况。
- 手机端需提供系统文件选择、导入校验结果、错误行定位、模板导出/分享和覆盖前确认。

P0：完整阶段状态机

八、每回合展示顺序
- 开启贷款时严格按以下顺序展示：新回合横幅 → 开盘前事件弹窗（有事件时）→ 银行贷款期 → 开盘前交易 → 开盘结果 → 收盘前新事件弹窗（有新事件时）→ 收盘前交易 → 收盘结果 → 银行还贷期（存在真人未结清贷款时）→ 下一回合/最终结算。
- 未开启贷款时跳过两个银行阶段；没有事件时跳过对应事件弹窗，但不能跳过交易和结果阶段。
- 每个 phase 的弹窗只由服务端 phase 驱动。轮询、WebSocket 和本地动画同时到达时必须去重，不能重复弹窗或提前进入下一阶段。
- 阶段弹窗、事件弹窗、结果弹窗和新回合横幅都需有轻量进入/离开动画；外接键盘回车在阶段结算窗口默认执行主确认按钮。

九、事件抽取、重新预测与保密
- 开盘前未抽到事件时，收盘前仍可进行一次新的事件抽取；不得因为 openingEvent 为空就在客户端跳过 closing event API 状态。
- 开盘前已抽到事件时，进入收盘前不重复弹出同一事件；服务端会重新判断该事件是否对收盘生效，并在生效时重新生成影响幅度，不沿用开盘结果。
- 如果服务端返回收盘前全新事件，则按收盘前新事件弹窗展示；手机端不得把开盘事件和新事件合并成一条本地记录。
- 价格公布前只展示事件名称、描述、类型、相关度、可信度、意外程度和强度，不展示是否生效、方向结果、幅度、原因、市场状态或价格结果。
- 开盘结果/收盘结果公布后再展示无影响、轻微、常规、强烈档位、实际幅度和自然语言原因。
- 不直接显示 STRONG_DOWN、LOW 等内部枚举；使用中文、面向玩家的结果和风险文案。

十、事件与股票本身走势衔接
- 展示后端 V2 价格拆解：基础趋势/动量、事件传导、中枢回归、动态噪声、订单流和总变化；客户端不得自行叠加百分比。
- 事件影响包含相关度、可信度、意外程度、强度、市场状态适配、传播切片和波动率封顶，手机端仅按返回值展示。
- 事件可能被市场提前消化、被过热/超卖环境放大或吸收，并可跨阶段衰减；说明书需解释“事件发生”不等于“价格必然按最大幅度变化”。
- “事件最小影响幅度”解释为事件生效后的原始幅度下界，用于防止已判定生效的事件只产生接近 0 的无感变化；最终幅度仍可能被适配、衰减、回归、噪声和价格上限调整。

P0：交易与走势图

十一、输入即保存
- 股数输入完成后短延迟自动提交，不再要求点击提交按钮；点击 25%、50%、75%、100% 和“全部”立即提交。
- 买入“全部”表示按实际开盘价使用全部可用现金，允许超过普通单笔股数上限；普通 100% 只使用当前普通订单额度。
- 卖出“全部”必须提交全部可卖持仓，不得受普通单笔上限影响。
- 输入 0 表示撤单；请求使用唯一 clientRequestId，快速连续修改只保留最新版本并避免旧响应覆盖新输入。
- 倒计时结束后立即禁用输入框、滑块、百分比、“全部”和撤单；阶段切换后重新按新 phase 解锁，不能永久锁死。
- 操作栏显著标明当前为“买入”或“卖出”，使用一致但不过度依赖颜色的状态、图标和文字。

十二、走势图粒度
- 支持 1、2、3、5、10 回合查看。1 回合表示每回合独立展示；N 回合表示每连续 N 个回合聚合成一个图形，不是只显示最近 N 回合。
- 聚合组展示区间开盘、最高、最低、收盘，并正确聚合事件、普通成交、个人成交、强制卖出数量和成交量；末尾不足 N 回合也需显示。
- 长局在手机横屏/竖屏下支持水平滚动、缩放或密度自适应，坐标文字与浮层不能遮挡。
- 最近成交列表可滚动查看全部当前返回记录，保留买卖方向、玩家、股数、成交价和回合信息。

十三、收益率排名
- 排名主排序键为相对各自初始资金的收益率，收益率相同时再按净资产和稳定顺序处理。
- 每行显示名称、玩家/AI 类型、持仓股数、可用资金、净资产和收益率；当前玩家仅高亮一次。
- 使用贷款时净资产必须扣除全部银行本金与未付利息，不能用现金加股票市值冒充净资产。

P0：AI 自主投资架构

十四、Thesis 与目标敞口
- 展示并兼容 AI 的活动投资观点：thesisId、版本、CREATE/KEEP/ADJUST/REPLACE/CLOSE、市场判断、方向、建立价格、目标股票敞口、置信度、复核周期、有效期、理由和结构化失效条件。
- 模型只输出投资观点和 0%～300% 目标股票敞口，不直接输出 BUY/SELL、股数、贷款金额或银行；后端根据目标与实际敞口生成订单和融资。
- 手机端不得在每次刷新时重新触发模型；只展示服务端 CACHE、FAST、STRONG、UNRESOLVED 等决策状态与最终执行结果。

十五、防止反复买卖
- 复用后端调仓缓冲、最小交易资产占比、最短持有回合、反向冷却、单回合换手上限、最大预估冲击和普通/高紧急度仓位步长。
- KEEP 或目标差异处于缓冲带时不应生成交易；重要新证据、观点失效、到期复核或风险强制降杠杆时才允许明显调整。
- 同一回合不能因多次模型响应出现先买后卖；手机端按服务端已执行决策去重，不基于中间推理文本提前修改持仓。
- 模型超时、格式无效或不可用时，后端可能沿用活动观点或使用确定性 fallback；界面应明确等待/降级状态，不把失败当成卖出信号。

十六、低 Token 快速决策
- 原生端只传递场次与玩家选择，不拼接完整历史行情 Prompt。后端使用冻结快照、紧凑 DecisionPacket、摘要指标、Evidence Gate 和按需 FAST→STRONG 升级。
- 同一冻结快照复用缓存；第二阶段只有真实新快照/新证据才重新判断，避免重复消耗 Token。
- 大量 AI 决策并发时页面保持可操作，使用状态更新而非等待单个长 HTTP 请求。

P0：多银行贷款系统

十七、银行阶段与时间规则
- 开启银行贷款后增加开盘前银行贷款期和收盘后银行还贷期；两阶段可分别配置是否倒计时及 3～600 秒时长。
- 未开启倒计时时 phaseEndsAt 为空，界面显示“不限时”，不能出现本地自动倒计时；所有有效真人点击完成后推进。
- 多人银行页底部展示有效真人玩家头像、名称和完成状态；AI 不占完成席位，玩家提前完成不会阻止 AI 在开盘决策时融资。
- 收盘结果确认后，若单人没有未结清本金/利息，直接跳过还贷期；多人中所有有效真人都无未结清贷款时也直接跳过。任意有效真人仍有债务则正常进入还贷期。

十八、多银行独立账户
- 银行名称使用顶部 Select 切换，不使用横向滑动银行卡片。
- 每家银行独立维护授信账户、贷款合同、借款冷却、本金、利息、期限、状态和流水；在一家银行借款后仍可切换下一家银行继续申请。
- 借款和还款请求必须携带 productCode。还款只作用于当前银行，不能误还其他银行。
- 单家银行初始资金额度独立计算，但总债务/净资产、总股票敞口、LTV、禁借、强平和违约按全部银行债务合并判断，不能通过切换银行绕过全局风控。
- 顶部债务摘要显示有债务银行数、总有效债务、总敞口、总 LTV 和全局风险；银行弹窗指标区显示本行额度、本金、利息和最近到期。

十九、贷款、计息、还款与延期
- 每次借款形成独立合同，贷款期限可在 1 回合至该银行配置上限内选择；借款当回合收盘开始按未偿本金计简单利息，不利滚利。
- “计息 +0”中的现金变化为 0 代表利息计入未付利息而非立即扣现金；流水应分别展示本金变化、利息变化和现金变化。
- 还款先付本行未付利息，再按最早到期合同归还本金；买单已冻结现金不可用于还款。
- 还款 25%/50%/100% 保留四位小数。现金足够时 100% 必须精确还清 0.6 等小数尾款；现金不足时最多提交可用现金并正确保留剩余债务。
- “本行贷款”按最新合同在前、每页 3 条，并按银行记住所选页码；切换银行后只显示该银行合同与流水。
- 已结清合同继续显示原借款金额和已还本金，不能只显示两个 0；银行流水保留借款、计息、主动还款、AI 还款、延期、到期还款、强平和违约记录。
- 未到期且未进入禁借/强平时，每笔合同最多延期 2 次。单次延期范围与所属银行贷款期限一致，例如贷款期限为 1～10 回合，延期也可选 1～10 回合。
- 延期费为剩余本金 0.5%，立即扣可用现金；每延期一次，每回合利率增加 0.2 个百分点，并展示原到期回合、当前到期回合、延期次数和累计延期回合。

二十、风险、到期与强平
- 展示 NORMAL、WARNING、BLOCKED、LIQUIDATION、DEFAULTED 的中文状态，不直接向玩家显示内部英文枚举。
- 到期或最终回合先使用现金还款，不足时按收盘价强制卖股；仍无力清偿则违约。
- 强制卖出的股票计入收盘卖出总量和订单流价格影响，因此可能影响收盘价；图表和收盘结果需区分普通卖出与强制卖出。
- 多银行强平按合并债务规划卖股数量，所得现金再按到期和风险优先级分配到各银行；手机端不得自行决定还款顺序。
- AI 目标敞口超过 100% 时可由后端选择仍有额度的低成本银行；目标降至 100% 以下时自动按后端顺序还债。

P0：恢复、暂停与异常处理

二十一、恢复游戏与重新开始
- 检测到可恢复场次时，不要只显示“正在恢复游戏”。展示明确的“恢复游戏”和“重新开始”选项，并说明恢复会继续原存档、重新开始会结束旧场次。
- 恢复失败时保留重试和重新开始；不能因为一次请求超时就判定存档损坏。
- 恢复后校准当前回合、阶段、剩余时间、订单、事件确认、银行选择、贷款分页、房间成员完成状态和 AI 任务状态。
- 单人离开活动场次按现有规则暂停；返回后继续。多人离开不应由单个客户端暂停全房间。

二十二、幂等、弱网和超时
- 下单、撤单、阶段确认、借款、还款、延期、密钥使用和重开均使用唯一请求编号；重试同一操作必须复用原请求编号。
- 请求成功但响应丢失时先重新拉取场次确认结果，不盲目重复扣款、还款或延期。
- 服务端阶段已经推进时，手机端应关闭过期弹窗、取消旧倒计时和输入请求，不再提交上一阶段动作。
- Redis/WebSocket 不可用时允许后端降级，手机端使用低频同步兜底；不得因实时连接断开清空当前游戏状态。

P0：完整游戏说明书

二十三、说明书内容
- 说明书覆盖单人、单人 AI、多人、多人 AI 的开始方式、创建/加入流程、AI Key 选择、房间完成机制和阶段顺序。
- 解释事件发生概率、生效概率、最小/最大影响幅度、类型、相关度、可信度、意外程度、强度、市场适配、衰减、噪声、均值回归、订单流和价格封顶。
- 解释每个 AI 参数、允许留空时的默认行为、建议区间、Thesis 生命周期、目标敞口、调仓保护和模型降级。
- 解释每个银行参数、建议值、独立额度与全局风险、计息、贷款期限、延期、到期、强平、违约及已结清记录。
- 解释作者版本标识、排行榜归组、游玩密钥类型、次数和状态。
- 所有规则随服务端/Web 规则更新同步维护，不能保留“有债务不能切换银行”“延期只能 1～2 回合”“始终进入还贷期”等旧文案。

原生端最终验收清单
1. 单人、单人 AI、多人、多人 AI 各完整运行至少 3 回合，阶段顺序与 Web 一致且无重复弹窗。
2. 验证开盘无事件而收盘抽到事件、开盘事件收盘重新预测、结果公布前不泄露事件结果。
3. 验证输入即下单、0 撤单、买入全部、卖出全部、倒计时结束锁定和网络重试不重复成交。
4. 验证 1/2/3/5/10 回合聚合语义、长局滚动、事件标记、普通成交与强平标记。
5. 验证收益率排名和持仓/现金字段，贷款后净资产、收益率与排行榜均扣除总债务。
6. 验证 AI 数量超过 8、编辑器两张一页、风格默认联动、作者 Key/玩家 Key、自主 Thesis 与防反复交易状态。
7. 验证两个以上银行同时借款、切换银行独立还款、各银行合同/流水隔离以及全局 LTV 无法被绕过。
8. 验证含四位小数债务点击 100% 完全结清；已结清合同展示借款与还款；另一银行债务保持不变。
9. 验证贷款期限 10 回合时延期下拉为 1～10，延期 10 回合后到期回合正确增加 10；超过上限由服务端拒绝。
10. 验证不限时银行阶段无倒计时、限时阶段按倍速缩放、多人完成状态，以及全部真人无债务时自动跳过还贷期。
11. 验证版本标识不变继续进入同一排行榜，变更后进入新分组；覆盖所有游玩密钥范围、次数、禁用和删除状态。
12. 验证恢复/重开选择、暂停恢复、应用冷启动、后台恢复、断网重连、重复点击和服务端阶段已推进等异常场景。
