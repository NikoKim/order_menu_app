手机端预开发清单（基于 2026-07-21 Web 与 Flutter 顾客端差异盘点）

说明
1. 本文只记录尚未在 customer_frontend（Flutter）完整实现的能力，不重复列出已经具备的动态信息流、推荐/相关页签、动态搜索、话题、草稿、点赞、表情回应、评论/回复、动态隐私、聊天内分享和消息未读数等功能。
2. 后端已经为引用与 @ 提及预留统一数据结构和接口。手机端接入时应直接复用接口字段，不要在客户端解析正文来推断引用或被提及用户。

P0：本次新增能力的手机端接入

一、引用动态与引用评论
- Moment 模型解析 quote：type、momentId、commentId、author、momentTitle、content、createdAt、available、unavailableReason。
- 动态卡片和动态详情在正文下方渲染引用卡片。
- 动态引用卡片展示标题、作者头像/昵称、发布时间和三行省略正文。
- 评论引用卡片展示评论作者头像/昵称、发布时间、评论内容，并在底部弱化展示来源动态标题。
- 动态右上角菜单对本人和他人的可见动态都提供“引用动态”。
- 评论及回复的右上角菜单提供“引用评论”。
- 发布页增加可见动态搜索和单选引用模块；一条动态只能引用一个动态或一条评论。
- 发布/编辑请求接入 quotedMomentId、quotedCommentId；编辑已有引用时保留 quote 快照。
- 点击引用卡片进入来源动态，并在引用评论场景定位 commentId。
- 来源动态后续改为无权限时，引用卡片仍显示快照；进入详情后展示“该动态已被设置权限，无法查看详情”。
- 适配草稿、编辑、删除来源内容、分页中定位深层回复等边界场景。

二、动态与评论 @ 用户
- 发布动态正文输入 @ 时打开用户选择弹窗。
- 评论/回复输入 @ 时打开同一用户选择弹窗。
- 弹窗默认展示最近直接聊天用户，并支持按昵称搜索所有可用用户（含顾客与商家）。
- 支持连续选择任意数量用户、去重、删除正文中的 @ 后同步移除对应 mentionedUserIds。
- 发布/编辑动态请求接入 mentionedUserIds；评论/回复请求也接入 mentionedUserIds。
- Moment、MomentComment 模型解析 mentions，编辑时恢复已选择用户。
- 正文与评论中的 @昵称 使用加粗暖橙色；悬停/长按展示用户资料卡（头像、昵称、角色，以及按用户隐私权限决定是否展示的电话等资料），点击进入该用户的动态主页。提及当前登录用户时标注“自己”、展示本人完整资料，并进入自己的动态管理页。
- 处理同名、用户停用、搜索无结果、快速连续输入和光标中间插入等情况。

三、动态通知跳转与新通知类型
- 消息中心识别 MOMENT_LIKED、MOMENT_COMMENTED、MOMENT_REACTED、MOMENT_MENTIONED、MOMENT_COMMENT_MENTIONED、MOMENT_COMMENT_REPLIED、MOMENT_QUOTED、MOMENT_COMMENT_QUOTED。
- 完整展示服务端 content，不在手机端重新拼接通知文案。
- 点击通知先标记已读，再从 payload 读取 momentId、commentId，进入动态详情并定位评论。
- 引用来源或动态权限变化时，在目标页展示受限状态，不停留在空白页。
- 为动态互动、@、引用配置可辨识的通知图标，并保留现有 WebSocket 实时刷新和总未读徽标。
- 验证前台、后台恢复、推送点击冷启动三种入口的深链行为一致。

P1：此前 Web 已有、手机端尚未完整对齐的能力

四、评论多图
- Flutter 当前每条评论只支持一张 imageUrl；对齐 Web 为最多 6 张 imageUrls。
- 增加多选、横向预览、单张删除、失败重试、上传中禁发和图片九宫格查看。
- 兼容历史正文中遗留的评论图片 URL。

五、动态与评论的外部分享模式
- Flutter 当前主要支持分享到站内聊天；补齐“分享到其他应用”。
- 支持“可继续浏览动态列表”和“仅查看当前动态”两种分享范围。
- 评论外部分享应携带 commentId，落地后定位对应评论。
- 对接系统分享面板、Web 分享卡片 URL、冷启动/热启动深链与权限失效页。
- 接入分享统计字段 shareCount、appShareCount、externalShareCount；站内分享仅在聊天消息成功发送后计数，站外分享仅在系统分享面板确认完成后上报，打开面板、取消分享或仅复制链接不得计数。

六、动态图片上传体验
- 对齐 Web 的选择后本地预览、统一上传、逐张状态、失败保留与单张重试。
- 发布已成功但部分图片失败时，不丢失动态和待重试图片。
- 草稿与已发布动态编辑均需正确合并已有远端图片和本地待上传图片。

七、通知与列表细节对齐
- 消息中心点击普通业务通知目前主要执行已读，需统一补齐订单、反馈、家庭、聊天和动态的 payload 路由。
- 通知列表、首页入口和系统推送的未读数必须共享同一刷新结果，处理全部已读后的即时归零。
- 超长通知、评论和回复统一使用省略号规则，同时保留进入详情查看完整内容的能力。
- 未读口径与顾客端主壳保持一致：聊天总徽标排除已静音会话，单会话仍展示自身未读状态；通知以 readAt 是否为空为准，动态“相关”未读继续使用服务端阅读记录。
- “相关”动态页签直接显示 relatedUnreadCount 徽标；仅当相关列表中的未读动态卡片实际进入可视区域时批量调用已读接口，推荐列表和后台隐藏的动态页不消费未读，口径与 Flutter 现有实现一致。
- 聊天、通知、动态新内容及已读变化统一由 /ws/customer 的 CHAT、NOTIFICATION、MOMENT 模块实时驱动，接口轮询只保留低频兜底；断线重连后立即全量校准徽标。
- 所有相关导航栏、页签、消息中心入口和会话项同步显示徽标，收到消息、进入阅读、单条已读和全部已读后即时更新。
- 推荐与相关页签分别保存切换前一刻的列表、分页和滚动位置；在动态与聊天之间切换时，同时保留当前动态页签及该页签的最后浏览位置，返回后恢复而不是共用一份滚动位置。

八、展示样式与时间规则
- 引用动态/评论卡片使用白色背景，仅以弱化的左侧细线轻量分隔并与动态正文自然融合；不使用明显的上下分隔线、强调色边框、灰底或多余类型标签。
- 引用动态正文以纯文本最多展示 3 行，引用评论以纯文本最多展示 2 行，不保留正文富文本格式。
- 信息流动态卡片中的评论预览不显示“热门评论”和“x条评论”，使用更紧凑的内外边距和协调的正文字号。
- 信息流动态卡片中的评论预览同时展示评论发布时间，并复用统一的相对时间与具体时分规则。
- 信息流动态卡片仅在 rootCommentCount（直接评论数）至少为 2 时显示“展开更多评论”，回复数不得参与判断；按页无感追加其余评论并使用过渡动画，加载过程中保留当前评论且显示评论列表骨架，避免内容闪烁或整块刷新。展开状态始终提供“收起评论”，两个操作保持相同的水平起点，收起后恢复仅展示一条评论。
- 动态、评论、引用卡片、通知和会话列表复用同一相对时间规则。
- 不满 1 分钟显示“刚刚”，不满 1 小时显示“x分钟前”，不满 24 小时显示“x小时前”。
- 超过 24 小时但仍属于本地日历昨天时显示“昨天 HH:mm”；其余时间显示具体时分，当年使用 MM-DD HH:mm，跨年使用 YYYY-MM-DD HH:mm。
- 动态评论下的回复采用与评论一致的头像、昵称、发布时间、正文、图片和操作布局，并支持独立点赞；同一评论线程内按 createdAt、id 从早到晚稳定排序。
- 所有三点操作菜单打开后都要按实际尺寸校验视口边界：下方不足时显示在触发按钮上方，右侧或左侧不足时切换对齐方向，并使用顶层浮层避免被列表、卡片或滚动容器裁剪遮挡。
- 三点操作菜单不得使用会拦截页面滑动的全屏透明层；菜单打开后页面仍可正常滚动，开始滚动或点击菜单外任意位置时自动关闭。
- 热门话题、搜索话题、搜索引用动态、搜索提及用户、聊天用户搜索及其他异步列表在等待数据时展示与结果形态对应的骨架加载，不以纯文字“加载中”替代。

接口字段备忘
- 创建/编辑动态：quotedMomentId、quotedCommentId、mentionedUserIds。
- 创建评论/回复：mentionedUserIds。
- 动态响应：quote、mentions、rootCommentCount（仅直接评论数；commentCount 继续表示全部评论及回复数）。
- 动态响应分享统计：shareCount、appShareCount、externalShareCount。
- 评论响应：mentions。
- 引用评论详情：GET /api/moments/{momentId}/comments/{commentId}。
- @ 用户搜索：GET /api/moments/mention-users?query=xxx。
- @ 用户资料卡：GET /api/moments/users/{userId}/card（电话等敏感字段由服务端权限字段控制）。
- 外部分享完成上报：POST /api/moments/{momentId}/external-shares，仅在系统分享成功回调后调用。
- 通知 payload：至少读取 momentId、commentId、conversationId、orderId。

建议验收顺序
1. 先完成模型与 API 兼容，确保旧版本忽略新字段时不崩溃。
2. 完成引用卡片、引用入口和权限失效页。
3. 完成 @ 选择、光标插入和通知跳转。
4. 补齐评论多图与外部分享。
5. 最后覆盖 Android/iOS 的推送深链、弱网重试、草稿恢复和回归测试。
